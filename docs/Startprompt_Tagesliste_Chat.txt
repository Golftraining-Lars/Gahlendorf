ABLAUF BEI JEDER ÄNDERUNG
1. Beide Repos (mit add_repo, Zugriff „push“ für das Daten-Repo) FRISCH klonen: git clone --depth 1 … – nie aus einer alten Kopie weiterarbeiten. Einmal: npm install im App-Repo.

3. Änderungen NUR mit node tools/wbcli.js apply <workbook.json> ops.json (oder „script“). Nie das JSON von Hand ändern. Beispiele für ops.json (eine Liste, "who":"Tagesliste-Chat"):

     ACHTUNG Kostenplan-Regel: Steht die Nr. im Blatt Kostenplan (Spalte A), Status und Datum DORT setzen: {"op":"sets","sheet":"Kostenplan","key":154,"cells":{"2":"erledigt","3":<heute>}}
   - neuer Termin (Spalte Z = 25): {"op":"sets","sheet":"Renovierungsplan","key":154,"cells":{"25":<Datum als Zahl>}}
   - Bemerkung (Spalte M = 12, max. ca. 450 Zeichen, Neues vorne mit Datum): {"op":"set","sheet":"Renovierungsplan","key":154,"c":12,"input":"24.11.: … | bisheriger Text"}
   - neue Aufgabe: {"op":"task","fields":{"B":"…","D":2,"F":"Elektro","G":"Eigenleistung","Z":"30.11.2026","M":"…"}}
   - Wissensspeicher (JEDE Information zuerst dorthin): {"op":"ws","fields":{"nr":154,"thema":"…","typ":"Hinweis","inhalt":"…","quelle":"Lars (Tagesliste-Chat TT.MM.)"}}
   - zum Schluss Version um 0.01 erhöhen: {"op":"version","to":"8.14","date":"TT.MM.JJJJ","by":"Tagesliste-Chat"}
   Spalten Renovierungsplan: A Nr., B ToDo, C Status, D Prio, M Bemerkungen, N EIGENE Bemerkungen (= MEINE Notizen, NIE ändern), P Erledigt am, Z Fällig bis (eigenes Datum), AA Fällig bis (auto, nicht überschreiben). Das Änderungsprotokoll schreibt das Werkzeug selbst.
